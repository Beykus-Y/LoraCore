# LoraOS Kernel

Основное ядро операционной системы LoraOS для внутриигрового планшета.

## Описание

`LoraOSKernel` реализует полноценное ядро-супервизор, которое управляет жизненным циклом Lua-процессов в виртуальном компьютере планшета. Ядро выполняет BIOS/POST-подобную последовательность загрузки с проверкой ключевых систем и асинхронным запуском пользовательского shell.

## Состояния конечного автомата ядра

- `BOOTING` - Начальная загрузка ядра, отображение экрана загрузки
- `CHECKING_SYSTEM` - Асинхронная проверка системных файлов
- `BOOT_FAILED` - Ошибка загрузки, отображение детальной информации об ошибках
- `RUNNING` - Ядро работает, shell запущен и управляет экраном
- `SHELL_CRASHED` - Shell упал, но ядро продолжает работать (синий экран смерти)

## Процесс загрузки

1. **Инициализация** - Сохранение API и инициализация графического контекста
2. **Системные проверки** - Асинхронная проверка ключевых файлов:
   - `/boot/boot.conf` - Конфигурационный файл загрузки
   - `/bin/shell.lua` - Исполняемый файл пользовательского shell
3. **Анализ результатов** - Переход в состояние `RUNNING` или `BOOT_FAILED`
4. **Запуск shell** - При успешных проверках автоматический запуск `/bin/shell.lua`

## Рендеринг экрана

**Важно:** Рендеринг экрана загрузки происходит **непосредственно из Java-ядра** на клиенте с помощью `IKernelGraphics`. После перехода в состояние `RUNNING` ядро передает управление отрисовкой Lua-скриптам, которые работают через серверную систему GPU-команд.

### Методы рендеринга

- `renderBootScreen()` - Экран загрузки с логотипом LoraOS
- `renderCheckScreen()` - Отображение статуса системных проверок с индикаторами `[OK]`, `[FAIL]`, `[WAITING]`
- `renderBootFailedScreen()` - Детальная информация об ошибках загрузки
- `renderShellCrashedScreen()` - Синий экран смерти при крахе shell

## Асинхронные операции

Ядро выполняет **асинхронные** проверки файлов в VFS, что является причиной видимого статуса `[WAITING]` в интерфейсе. Все операции с файловой системой выполняются через `CompletableFuture` для обеспечения неблокирующей работы.

## Особенности реализации

- **Потокобезопасность** - Использует `ConcurrentHashMap` для хранения результатов проверок
- **Модульная архитектура** - Каждое состояние отрисовывается отдельным методом
- **Обработка ошибок** - Корректная обработка исключений при проверках и запуске shell
- **Предотвращение мерцания** - Инициализация фона экрана при загрузке для плавного перехода
- **Константы** - Все "магические числа" (размеры экрана, цвета) вынесены в именованные константы

## Использование

Ядро автоматически загружается при запуске планшета в Java-режиме. Для корректной работы требуется:

1. Файл `/boot/kernel.jar` в VFS планшета (содержит скомпилированный `LoraOSKernel`)
2. Файл `/boot/boot.conf` в VFS (конфигурация загрузки)
3. Файл `/bin/shell.lua` в VFS (пользовательский shell)

## Разработка

Для добавления новых проверок системы:

1. Добавьте путь в массив `SYSTEM_CHECKS`
2. Обновите логику отображения в `renderCheckScreen()`
3. При необходимости добавьте новые состояния в enum `State`

Для изменения цветовой схемы используйте константы в начале класса:
- `SCREEN_WIDTH`, `SCREEN_HEIGHT` - размеры экрана
- `BOOT_BACKGROUND_COLOR`, `FAIL_BACKGROUND_COLOR`, `CRASH_BACKGROUND_COLOR` - цвета фона
- `TEXT_COLOR_*` - цвета текста для различных состояний
