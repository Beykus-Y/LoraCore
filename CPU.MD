Это описание архитектуры процессора (назовем её **Lora-1**, исходя из контекста кода), основанное на предоставленном фрагменте реализации виртуальной машины.

---

# Спецификация архитектуры процессора Lora-1

## 1. Общий обзор
Архитектура представляет собой **32-битный RISC-подобный процессор** с фиксированной длиной инструкции. Процессор ориентирован на регистровую работу, имеет выделенную шину данных и встроенные механизмы симуляции физических параметров (температура, напряжение).

## 2. Регистровая модель
*   **Регистры общего назначения (GPR):** 16 регистров по 32 бита каждый ($R_0$ – $R_{15}$).
*   **Специальные регистры:**
    *   `R15`: Используется как **Stack Pointer (SP)** — указатель стека.
    *   `PC` (Program Counter): 32-битный указатель на адрес текущей инструкции.
*   **Флаги состояния (Flags):**
    *   `FLAG_ZERO`: Устанавливается, если результат операции равен 0.
    *   `FLAG_NEGATIVE`: Устанавливается, если результат операции меньше 0.

## 3. Формат инструкции (32 бита)
Все инструкции имеют фиксированную длину 4 байта. Декодирование происходит следующим образом:

| Биты | Название | Описание |
| :--- | :--- | :--- |
| **31 – 24** | `Opcode` | Код операции (8 бит, до 256 инструкций). |
| **23 – 20** | `rD` | Индекс регистра назначения (Destination). |
| **19 – 16** | `rS` | Индекс регистра источника (Source). |
| **15 – 0** | `Imm16` | Непосредственное значение (Immediate) или смещение. |

**Особенности интерпретации `Imm16`:**
*   **Unsigned:** Используется в логических операциях (`ANDI`, `ORI`).
*   **Signed (`simm16`):** Используется в арифметике (`ADDI`) и переходах. Приводится к типу `short` для расширения знака.

## 4. Система команд (Instruction Set)

### Группа 1: Передача данных
*   `MOV`: Копирование значения из `rS` в `rD`.
*   `LDI` (Load Immediate): Загрузка 16-битного числа в младшую часть `rD`.
*   `LUI` (Load Upper Immediate): Загрузка 16-битного числа в старшие 16 бит `rD` (используется для формирования 32-битных констант).
*   `LD` / `ST`: Чтение/запись в память по адресу, хранящемуся в регистре.
*   `PUSH` / `POP`: Работа со стеком. Стек растет вниз (SP уменьшается на 4 при PUSH).

### Группа 2: Арифметика и Логика
Все арифметические операции обновляют флаги `ZERO` и `NEGATIVE`.
*   **Целочисленные:** `ADD`, `SUB`, `MUL`, `DIV`, `MOD`.
*   **С константой:** `ADDI`, `SUBI` (используют знаковое 16-битное число).
*   **Специальные:** `POW` (возведение в степень).
*   **Логика:** `AND`, `OR`, `XOR`, `NOT`.
*   **Сдвиги:** `SHL` (влево), `SHR` (логический вправо). Величина сдвига берется из младших 5 бит `Imm16`.

### Группа 3: Управление потоком (Control Flow)
*   **Безусловные:** `JMP` (на адрес), `JMPR` (на адрес из регистра `rD`).
*   **Условные переходы:** Основаны на флагах:
    *   `JZ` / `JNZ`: Переход, если Zero / Not Zero.
    *   `JG`: Переход, если больше (не Zero и не Negative).
    *   `JL`: Переход, если меньше (Negative).
*   **Подпрограммы:**
    *   `CALL`: Сохраняет текущий `PC` в стек и прыгает на адрес.
    *   `RET`: Извлекает адрес из стека и возвращается.

### Группа 4: Ввод-вывод и Система
*   `INT`: Программное прерывание (вызов системного сервиса через шину).
*   `IN` / `OUT`: Чтение и запись в порты ввода-вывода.
*   `HLT`: Остановка процессора.
*   `DUMP`: Отладочный вывод состояния регистров.

### Группа 5: Физические параметры (Hardware Simulation)
Уникальная особенность архитектуры — возможность программного контроля "физики":
*   `GET_TEMP`: Получить текущую температуру кристалла.
*   `SET_VOLT`: Установить рабочее напряжение (влияет на стабильность).
*   `GET_CLOCK`: Получить текущую тактовую частоту.
*   `CPUID`: Получение метаданных процессора (ID, версия архитектуры, пределы разгона).

---

## 5. Обработка исключений
В процессоре реализован счетчик ошибок `errorCount`. Он увеличивается в случаях:
1.  Деления на ноль (`DIV`, `MOD`).
2.  Попытки выполнить неизвестный `Opcode` (генерирует `CPU FAULT` в логах).

## 6. Тайминги
Большинство инструкций выполняются за один цикл (в контексте VM), однако инструкция `WAIT` позволяет приостановить выполнение на заданное количество циклов (через возвращаемое значение в эмуляторе).

---

### Пример декодирования в коде:
```java
int opcode = (instr >>> 24) & 0xFF; // Берем первые 8 бит (крайние слева)
int rD = (instr >> 20) & 0x0F;     // Следующие 4 бита (23-20)
int rS = (instr >> 16) & 0x0F;     // Следующие 4 бита (19-16)
int imm16 = instr & 0xFFFF;        // Оставшиеся 16 бит
```
Эта структура позволяет упаковать всю необходимую информацию о команде в одно стандартное 32-битное целое число.
