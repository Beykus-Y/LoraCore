# Журнал изменений LoraCore

Все заметные изменения в этом проекте будут задокументированы в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
и этот проект придерживается [Семантического Версионирования](https://semver.org/spec/v2.0.0.html).



## [2.0.0] - 2026-07-17

### Добавлено

- Полностью нативная LoraOS, поставляемая внутри основного JAR и автоматически
  устанавливаемая на новый виртуальный диск без ручного копирования файлов.
- Двухступенчатый LoraBoot с выбором LoraOS/Recovery и автоматическим fallback
  на второй загрузочный слот.
- Терминальный shell с командами `help`, `about`, `hw`, `clear`, `ls`,
  `cat note`, `write note` и `world`.
- Постоянная LoraFS: автоматическое форматирование пользовательской области и
  проверенная сквозным тестом запись файлов через raw-disk MMIO.
- Read-only World Bridge ABI v1: позиция игрока, направление, блок в пределах
  обычного raycast и входной redstone-сигнал без возможности менять мир.
- Рецепты планшета и базового/улучшенного железа для полноценного получения в
  режиме выживания.

### Изменено

- Фабричный диск теперь всегда воспроизводимо создаётся с нуля и содержит только
  `system.bin` и `recovery.bin`; загрузочная конфигурация и таблица имеют формат
  LDB2.
- Версия мода и артефакта повышена до 2.0.0.
- Старый диск автоматически мигрируется при первом открытии; исходный файл
  сохраняется рядом как `disk.bin.pre-2.0.bak`. Диски LDB2 повторно не меняются.

### Удалено

- Java TabletOS и связанный с ним отдельный Gradle-подпроект, клиентский runtime,
  reflection RPC и устаревшая документация.
- Устаревшие `fileman.bin` и `test.bin` из исходников и фабричного образа.

### Проверено

- Полный boot реальных `bios.bin`/`disk.bin`, выбор Recovery, Enter/Backspace,
  форматирование и запись LoraFS, CPU/MMU/IRQ и сохранность миграционной копии.

## [1.2.2] - 2026-07-17

### Добавлено

- Новая архитектура виртуальной машины и LoraOS: MMU/paging, аппаратные IRQ,
  драйверы клавиатуры и GPU, а также обновлённый загрузочный конвейер.
- Воспроизводимая задача `generateKernel`, собирающая ASM, MAP и BIN из
  канонических исходников `os/src/kernel/**/*.lc`.
- Задачи `generateFirmware` и `generateSystemDisk`, которые перед сборкой JAR
  компилируют BIOS/bootloader и упаковывают актуальное ядро в загрузочный диск.
- Регрессионные тесты перезагрузки CPU, IRQ, очереди клавиатуры и 32-битных
  обращений через границу несмежных страниц, а также полный boot-тест образа.

### Исправлено

- `VirtualCpu.reset()` теперь сбрасывает счётчик тактов, состояние прерываний,
  счётчик пустой памяти и ожидающие IRQ.
- Fetch, загрузка, сохранение и стек корректно транслируют каждый байт при
  32-битном доступе через границу виртуальной страницы.
- Контроллер IRQ использует атомарные операции и не теряет параллельные запросы.
- Загрузка GPU-шрифта проверяет, что ресурс прочитан полностью.
- `disk.bin` больше не содержит устаревшее ядро, вызывавшее синий экран и
  `Memory access violation: address 0xFFFFFFD8` при открытии планшета.
- Драйвер LoraOS вычисляет MMIO-адрес GPU по размеру устройства из PnP; команды
  интерфейса больше не записываются внутрь VRAM при разрешении 960×540.
- Терминал LoraOS обрабатывает Enter и Backspace как управляющие клавиши вместо
  вывода музыкального знака и неизвестного глифа.

### Документация

- Добавлены актуальные описания проекта для Modrinth и CurseForge.
- Удалены устаревшие инструкции про Lua/`boot.lua`; описание планшета приведено
  в соответствие с аппаратной VM Lora-1 и LoraOS.

## [1.2.1] - 2025-08-08

### 🔧 Добавлено

- **Улучшенная система планшета**: Расширены возможности виртуального компьютера планшета
- **Улучшенный пользовательский интерфейс**: Совершенствование интерфейсов для взаимодействия с ИИ и жителями
- **Архитектурные улучшения**:
  - Модульная структура с разделением ответственности
  - Улучшенная обработка ошибок

### 🔧 Изменено

- **Рефакторинг кода**: Полная реорганизация кода для улучшения читаемости и поддерживаемости
- **Система сборки**: Обновлены Gradle задачи для сборки мода
- **Документация**: Добавлены подробные руководства разработчика и архитектурная документация

### 🔧 Исправлено

- **Проблема с размером пакетов**: JAR-файлы ограничены ~22KB для стабильной передачи
- **Совместимость**: Полная обратная совместимость с существующим API
- **Стабильность**: Улучшена обработка ошибок и восстановление после сбоев

## [1.2.0] - 2025-08-05

### 🔧 Добавлено

- **Эмуляция ПК и операционной системы на основе Lua (LoraCore OS)**  
  Введена полноценная система виртуального компьютера, запускаемая с помощью **планшета**. Игрок может взаимодействовать с терминалом, запускать скрипты и использовать встроенные утилиты. (Как open computer или computercraft)
  (Для установки ОС требуется открыть планшет, зайти в папку с миром - loracore_vfs/{UUID}/ создать файл boot.lua отвечающий за точку входа в ОС)

- **Предмет «Планшет» (Tablet)**  
  Новый крафтовый предмет с временной текстурой, который открывает интерфейс виртуального компьютера при правом клике. Планшет служит основным интерфейсом для взаимодействия с эмулятором.

## 🚀 Планы на будущее (Roadmap)

Мы активно развиваем концепцию **интегрированного ИИ-ассистента внутри виртуального ПК**. В ближайших обновлениях ожидайте:

- **AI Assistant в терминале**  
  Возможность вызывать ИИ прямо из командной строки планшета:  
  `> ask "Как сделать алмазную кирку?"`

- **Автономные скрипты с ИИ**  
  Запуск Lua-скриптов, которые используют ИИ для генерации решений:  
  `> run quest_helper.lua` → автоматический анализ квестов и советы.
  
- **Модульная система приложений**  
  Возможность устанавливать "приложения" на планшет: календарь, калькулятор, ОС.

- **Улучшенная текстура планшета и GUI-темы**  
  Замена временной текстуры на качественную.

## [1.1.0] - 2025-07-13

### Добавлено
- **Система Дружбы с Жителями**: Внедрена комплексная механика отслеживания отношений игрока с каждым жителем.
- **Повышение дружбы**: Уровень дружбы увеличивается за успешное выполнение квестов (+10 очков).
- **Система Подарков**: Игроки теперь могут дарить жителям предметы, держа их в руке и нажимая новую кнопку «Подарок» в диалоговом окне. Реакция и количество очков дружбы зависят от профессии жителя и ценности подарка (от +20 за любимый предмет до -15 за неприятный).
- **Понижение дружбы**: Атака на жителя теперь значительно понижает уровень дружбы с ним (-25 очков) и выводит в чат соответствующее уведомление.
- **Отображение в GUI**: Текущий уровень дружбы теперь отображается в правом верхнем углу окна диалога с жителем.

### Изменено
- **Контекст диалогов для ИИ**: Искусственный интеллект теперь получает информацию о текущем уровне дружбы с игроком. Это позволяет ему менять тон ответов — от дружелюбного при высоких значениях до неприязненного при низких.
- **Усилен промпт для генерации квестов**: Системный промпт для диалогов был сделан более строгим, чтобы заставить модель ИИ надежнее придерживаться JSON-формата и не игнорировать генерацию квестов, особенно при использовании прокси-серверов.

### Исправлено
- **Предотвращение сбоев при сохранении**: В компонент `VillagerDataComponentImpl` и `PlayerAskHistoryComponentImpl` добавлены проверки на `null` при записи NBT-данных. Это повышает стабильность и предотвращает потенциальные сбои при сохранении мира.

## [1.0.4] - 2025-07-13

### Добавлено
- **Отправка сообщений по Enter**: В окне диалога с жителем теперь можно отправлять сообщения нажатием клавиши Enter, что улучшает удобство использования.
- **Прокрутка диалога**: Реализована полноценная прокрутка колесом мыши в окне диалога с жителем, что предотвращает наложение длинных диалогов на элементы интерфейса.

### Изменено
- **Внешние файлы промптов**: Все системные промпты для ИИ вынесены из кода во внешние файлы (`.prompt`), загружаемые через `PromptManager`. Это упрощает их редактирование и кастомизацию без необходимости перекомпиляции мода.
- **Унификация `AiService`**: Код для взаимодействия с API был централизован. Теперь все запросы проходят через единый метод `executeChatCompletion`, что повышает стабильность и упрощает добавление новых функций ИИ.

### Исправлено
- **Наложение текста в диалоговом окне**: Устранена проблема, при которой длинные диалоги накладывались на поле ввода. Это исправлено внедрением механизма отсечения (`scissor`) и прокрутки контента.
- **Серверная ошибка получения языка игрока**: Исправлена ошибка компиляции в `StructureNameManager`, связанная с попыткой вызова несуществующего метода `getLanguage()` на серверной сущности игрока. Теперь используется корректный метод `player.getClientOptions().language()`.

## [1.0.3] - 2025-07-12

### Добавлено
- **Новый интерфейс для команды `/ask`**: Команда `/ask` теперь открывает полноценный графический интерфейс для чата с ИИ, заменяя старую систему вывода ответов в игровой чат.
- **История диалога с ИИ**: Новый интерфейс поддерживает прокручиваемую историю сообщений, которая сохраняется для игрока.
- **Компонент для хранения истории**: Для реализации истории чата был добавлен новый компонент `PlayerAskHistoryComponent` с помощью Cardinal Components API.

### Изменено
- **Улучшено распознавание контекста ИИ**: Кардинально переработана логика формирования запросов к ИИ. Теперь актуальная информация об игроке (инвентарь, биом, координаты) добавляется в конец каждого запроса, что заставляет модель уделять ей повышенное внимание и давать более релевантные советы.
- **Поддержка контекста диалога**: ИИ теперь получает полную историю предыдущих сообщений, что позволяет ему "помнить" контекст беседы и отвечать на уточняющие вопросы.
- **Увеличен лимит ответа ИИ**: Максимальное количество токенов в ответе от API увеличено с 250 до 1024, чтобы предотвратить обрывание длинных и подробных ответов.
- **Форматирование ответов ИИ**: В новом окне `/ask` реализован парсер Markdown-подобной разметки. Текст, окруженный `**`, теперь корректно отображается как жирный.
- **Серверная логика**: Обработчик пакета `AskAiC2SPacket` теперь не отправляет сообщение в чат, а обновляет `PlayerAskHistoryComponent` на сервере с последующей синхронизацией на клиент.

### Исправлено
- **Ограничение на ввод символов**: Снято ограничение на ввод в 32 символа в полях ввода в диалоге с жителями и в окне чата с ИИ. Новый лимит — 256 символов.
- **Структура сетевого кода**: Исправлена ошибка в файле `ModNetworking.java`, где один обработчик пакетов был ошибочно вложен в другой, что вызывало каскадные ошибки компиляции.

## [1.0.2] - 2025-07-11

### Изменено
- **Лицензия проекта изменена с CC0-1.0 на MIT.**
- Улучшена логика генерации квестов: теперь используется единый JSON-ответ от API, что повышает надежность и устраняет визуальные баги в диалогах.
- Временно отключена генерация квестов для профессии `NITWIT` из-за некорректных ответов API.

### Исправлено
- Устранена ошибка `IllegalStateException: Expected BEGIN_OBJECT but was STRING`, возникавшая, когда API возвращало обычную строку вместо JSON. Теперь используется JSON-режим и добавлена защитная обработка.
- Тег `[QUEST_OFFER]` больше не появляется в диалогах благодаря принудительной очистке на стороне сервера.

### Документация
- Добавлен файл `CHANGELOG.md` для отслеживания изменений.
